# Velox Trade — Telegram-бот (отдельный процесс)

Это тот же бот, что раньше отвечал через вебхук на сайте (`src/app/api/telegram/webhook`), но
вынесенный в один файл (`bot.js`), который можно запустить на любом обычном Node.js-хостинге —
без домена, без вебхука, без ничего лишнего. Внутри — **long polling**: скрипт сам, в цикле,
спрашивает у Telegram "есть новые сообщения?", поэтому ему не нужен публичный HTTPS-адрес.

Ничего из функциональности не потеряно:

- Главное меню и подменю «Обратная связь» (Пополнение/вывод, Поддержка, Сотрудничество)
- Привязка Telegram к существующему аккаунту и регистрация нового аккаунта через `/start <код>`
- Пересылка сообщений администратору в личку

## Что НЕ входит в этот файл (и почему это нормально)

Рассылка из админки (`/admin/ads`) и уведомления о новых заявках на продажу (`/admin/sell-requests`)
по-прежнему отправляются **прямо с сайта** через Bot API (им для этого не нужен ни вебхук, ни этот
процесс — они просто вызывают `sendMessage`/`sendPhoto` напрямую). Так что их трогать не нужно,
они продолжат работать без изменений.

## Установка

```bash
cd telegram-bot
npm install
cp .env.example .env
```

Заполни `.env` — все значения бери из `.env.local` сайта (это те же переменные, один в один):
`TELEGRAM_BOT_TOKEN`, `TELEGRAM_ADMIN_CHAT_ID`, `FIREBASE_ADMIN_PROJECT_ID`,
`FIREBASE_ADMIN_CLIENT_EMAIL`, `FIREBASE_ADMIN_PRIVATE_KEY` (ключ должен остаться в кавычках, с `\n` внутри).

Запуск:

```bash
npm start
```

Если увидел в консоли `✅ Бот @имя_бота запущен (long polling)` — всё работает, можно писать боту в Telegram.

## ⚠️ Важно: вебхук и polling несовместимы

У Telegram бот может получать сообщения **только одним способом одновременно** — либо через вебхук,
либо через long polling. При старте `bot.js` сам вызывает `deleteWebhook`, так что если на сайте был
настроен вебхук (`/api/telegram/webhook`), он автоматически отключится, и отвечать на сообщения
будет уже этот процесс. Если запустишь и сайт с вебхуком, и этот скрипт одновременно — работать
стабильно будет только то, что запущено позже (последний вызов `setWebhook`/`deleteWebhook` побеждает).
Проще всего выбрать что-то одно: раз ты разворачиваешь этот файл — просто используй его,
а вебхук на сайте можно больше не настраивать (или явно отключить: `deleteWebhook` уже это делает).

## Куда задеплоить

Подходит любой хостинг, который умеет держать процесс постоянно запущенным (это НЕ serverless-функция,
а обычный долгоживущий процесс):

- **Railway / Render (Background Worker)** — залей эту папку как отдельный репозиторий или под-папку,
  команда запуска `npm start`, добавь переменные окружения из `.env` в настройках сервиса.
- **VPS (любой)** — залей папку, `npm install`, дальше держи процесс живым через **pm2**:
  ```bash
  npm install -g pm2
  pm2 start bot.js --name velox-bot
  pm2 save
  ```
- **Systemd на своём сервере** — заведи unit-файл, который делает `node bot.js` в этой папке
  с переменными окружения из `.env` (через `EnvironmentFile=`).

Так как это отдельный Node-проект (свой `package.json`), деплоить его можно независимо от Next.js-сайта —
на другом хостинге, в другом репозитории, как угодно. Единственное, что их связывает — общий проект
Firebase (те же ключи Admin SDK) и общий токен бота.

## Логи и перезапуск при сбое

Скрипт сам перезапускает цикл опроса при сетевых ошибках (пауза 3 секунды), но если процесс упадёт
целиком (например, кончится память) — рекомендуется что-то, что само его перезапустит: `pm2` делает
это по умолчанию, у Railway/Render такое поведение тоже встроено для воркеров.
