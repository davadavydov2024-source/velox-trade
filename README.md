## ОБЯЗАТЕЛЬНО перед деплоем — добавить правила Firestore

В firestore.rules (отдельный файл, не в этом репозитории — деплоится через
Firebase Console или `firebase deploy --only firestore:rules`) добавьте:

    match /cases/{caseId} {
      allow read: if true;
      allow write: if isAdmin();
    }
    match /caseOpenings/{openingId} {
      allow read: if isAdmin() || (isSignedIn() && resource.data.userId == request.auth.uid);
      allow write: if false;
    }

Без этого блока публичная страница /case не увидит кейсы (permission-denied),
как уже было с directConversations ранее.

## Как это работает
1. Админ создаёт кейс (фото, название, цена открытия) в /admin/cases.
2. Внутри кейса добавляет предметы: фото, название, "стоимость выигрыша" (₽,
   зачисляется на баланс при выпадении) и "вес" (относительный шанс — как в
   Колесе Фортуны, не обязательно в сумме 100).
3. Пользователь заходит на /case, выбирает кейс, жмёт "Открыть за N ₽".
4. Сервер (api/cases/open) в одной транзакции: проверяет баланс, честно
   выбирает предмет по весам (Math.random), списывает цену и зачисляет
   стоимость выигрыша одним изменением баланса, пишет запись в caseOpenings.
5. Результат показывается модалкой с выигранным предметом.

## Что НЕ реализовано (можно доделать в следующей сессии)
- Анимация прокрутки рулетки при открытии (сейчас — мгновенный результат в
  модалке, без CS:GO-style scroll-анимации).
- История открытий кейсов в профиле пользователя.
- Ограничение "открыть кейс не чаще раза в N секунд" (антиспам) — сейчас можно
  открывать без ограничений, кроме баланса.
- Мобильная нижняя навигация (MobileTabBar) — ссылку на /case туда не добавлял,
  только в десктопную шапку (Header.tsx).
