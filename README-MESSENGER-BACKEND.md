## Загрузка медиа (для сессии B)
1. `POST /api/messenger/upload-ticket { kind }` -> `{ ticket, pathPrefix, maxBytes, contentTypes }`
   kind: image | voice | videoNote | file | story-image | story-video | avatar
2. Прямая загрузка (npm-пакет `@vercel/blob` уже в проекте):
   `import { upload } from "@vercel/blob/client"; const blob = await upload(pathPrefix + name, file, { access: "public", handleUploadUrl: "/api/messenger/upload", clientPayload: ticket });`
3. `blob.url` -> в `send { kind, mediaUrl, duration?, waveform?, width?, height? }`, `stories`, `profile.photoURL`, `chat-info.photoURL`.
Лимиты: фото 10 МБ, голос 5 МБ (≤10 мин), видеокружок 15 МБ (≤60 с), история-видео 25 МБ, файл 20 МБ (pdf/zip/txt).
Запись в браузере: `MediaRecorder`; на iOS Safari голос — `audio/mp4`, видео — `video/mp4`; на Chrome — `audio/webm`, `video/webm`. Формат берите из `recorder.mimeType`.
Чтение: списки папок — `messengerUserFolders/{uid}/folders`; настройки чатов — `messengerUserChats/{uid}/chats`. Истории — только через `GET /api/messenger/stories` (опрос раз в 30–60 с).
Отправитель блокировки получает 403 «Нельзя писать этому пользователю». В канале не-админ получает 403.

## Известные ограничения
Тип загруженного файла проверяется по заявленному content-type (прямая загрузка в Blob не даёт проверить байты); отдаются файлы только как audio/video/image/pdf/zip/txt, HTML и SVG запрещены.
Нет: «удалить только у себя» на сервере, поиск по сообщениям, сквозное шифрование.

# Обновление 3: папки, каналы как в Telegram, Mili Premium, стикеры

## Папки (`lib/messenger/folders.ts`, общий для всех экранов)
Чат может лежать сразу в нескольких папках. Правила папки: `includeTypes` (`dm`/`group`/`channel` — все чаты этого типа, включая НОВЫЕ; `unread` — любой чат с непрочитанными)
и ручной список (`chatIds` / `folderIds` у чата). Новое сообщение или новый чат сами появляются во всех подходящих папках без ручных действий.
Функции: `chatInFolder`, `foldersForChat`, `folderUnread` (бейдж вкладки), `allUnread` (вкладка «Все»; архив и чаты «без звука» в бейдж не входят).

## Каналы
- `chats { type:"channel", title, description?, handle? }` — с `handle` канал публичный (@адрес, поиск, вход по ссылке), без — приватный (вход по пригласительной ссылке).

- `join-chat { handle }` или `{ code }` — подписаться/вступить; выйти — `members { action:"leave" }`. Лимит: канал 5000, группа 200.
- `invite { chatId, action:"create"|"revoke" }` — пригласительная ссылка `/m?join=<code>` (для публичного канала: `/m?join=@handle`). Страница `/m` читает `?join=` и показывает карточку с кнопкой «Подписаться».
- Посты: пишут только админы. Просмотры: `channel-view { chatId, msgIds[] }` вызывать, когда пост попал в экран (один человек = один просмотр); число в `messages/{id}.views`. Реакции — обычные.
- Не сделано: комментарии к постам (обсуждения), планирование постов.

## Mili Premium
- Цена и срок: `lib/messenger/premium.ts` — **10 ⭐ на 30 дней** (меняется одной константой). Оплата с кошелька ⭐ на сайте (`users.starsWallet`, пополнение — страница «Пополнение ⭐»).

## Группы: права и роли как в Telegram

- **Поиск по сообщениям**: `GET search-messages?q=&chatId?`. **Приватность**: `profile { privacy:{ whoCanMessage, whoCanAddToGroups } }` (`everyone`/`nobody`), учитывается при создании чатов и добавлении в группы.
- Автоудаление: клиент скрывает сообщения с `expireAt` в прошлом; физически чистит cron `/api/cron/messenger-cleanup` раз в сутки (заменить `vercel.json` на приложенный, `CRON_SECRET` уже есть).
- Большие каналы: счётчики непрочитанных пишутся пачками, пуши получают первые 1000 подписчиков (ограничение производительности).

# Обновление 5: «MiliGram Push», сеансы, рассылки, удаление для всех

## «MiliGram Push» — служебный чат (как чат «Telegram» с уведомлениями)
У каждого пользователя появляется служебный чат от верифицированного аккаунта **MiliGram Push** (`@miligram`, uid `miligram`, зарезервирован — занять нельзя). Отвечать в нём нельзя (`chat.service: true`), ему нельзя написать и найти через поиск. Сюда приходят уведомления о входе и рассылки админа.

## Сеансы и уведомление о новом входе
- Клиент при каждом запуске/входе вызывает `POST /api/messenger/session { deviceId }` (случайная строка 16–64 символа, одна на устройство, хранить в localStorage) и во ВСЕХ запросах шлёт заголовок `X-Miligram-Device: <deviceId>`.
- Новое устройство при уже существующем сеансе = «новый вход»: сообщение от MiliGram Push в приложении + сообщение **в Telegram-бота Velox** (если Telegram привязан и уведомления в Telegram у человека не выключены): устройство, город/страна, IP, время, что делать, если это не вы. Первый вход (регистрация) не уведомляет; не чаще 3 раз за 10 минут.
- Список устройств: `GET /api/messenger/session?deviceId=` -> `{ sessions }`. Завершить: `POST session/terminate { id }`, `{ others:true, currentDeviceId }` или `{ everything:true }` (последнее ещё и сбрасывает вход на сайте).
- Завершённое устройство получает `401 { revoked:true }` на любой запрос (клиент должен выйти). Честное ограничение: чтение чатов напрямую из Firestore останется работать, пока не истечёт текущий токен (до часа); «завершить всё» (`everything`) отзывает вход полностью.

## Рассылки админа (как рассылка из официального канала)
В `/admin/messenger` блок **«Рассылка от MiliGram Push»**: текст до 3500 символов, адресаты (все / только Mili Premium / только с галочкой), «без пуша». Идёт пачками по 100 с индикатором, история последних рассылок. API: `POST /api/admin/messenger/broadcast` (продолжение — `broadcastId` + `cursor`).

## Удалить для всех
- `delete { chatId, msgId | msgIds[] (до 100) }` — «удалить для всех» (своё в любое время; чужое — если есть право «удалять сообщения»); `forMe:true` — только у себя.
- `clear-chat { chatId, forAll:true }` — **очистить историю у всех** (личный чат — любой из двоих; группа/канал — создатель или админ с правом удалять). До 2000 сообщений за вызов — повторять, пока `done:false`.

## Что сделать вам
Распаковать архив поверх проекта, заново вставить `firestore-rules-messenger-snippet.txt`, `git push`. Переменных не нужно. Для сообщений в Telegram-бот должен быть привязан Telegram к аккаунту Velox (это уже работает на сайте).

# Обновление 7: регистрация через Telegram-бота, доработанный интерфейс

## Регистрация (как просили): почта + пароль + ОБЯЗАТЕЛЬНЫЙ бот, код на почту не нужен
1. Человек вводит имя, @username, почту, пароль -> `POST /api/messenger/signup` создаёт пользователя и заявку на привязку Telegram.
2. Кнопка «Открыть бота в Telegram» (`t.me/<бот>?start=<код>`): человек жмёт «Старт» — существующий вебхук бота сам привязывает Telegram (`telegramLinks`), менять бота не нужно.
3. Экран опрашивает `GET signup?code=` (раз в 2,5 с); как только бот привязан, аккаунт создаётся и происходит вход автоматически.
- Один Telegram = один аккаунт MiliGram. Незавершённая регистрация живёт 30 минут, потом очищается. Старый `register` отключён (410), чтобы нельзя было обойти бота.
- Те, кто уже вошёл на сайте Velox: имя и @username, затем тот же шаг с ботом (если Telegram ещё не привязан).
- Имя бота берётся из `NEXT_PUBLIC_TELEGRAM_BOT` (по умолчанию `veloxtrade_robot`, как в остальном коде сайта).

## Интерфейс
- Экран **информации о чате** (нажать на шапку чата): профиль человека; для группы и канала — участники и роли, права, медленный режим, запрет пересылки, автоудаление, заявки на вступление, ссылка-приглашение, добавление по @username, назначение админов, заглушка, исключение, бан, выход/удаление.
- **Стикеры** (панель рядом с полем ввода, ссылка набора `/m?stickers=название`), **опросы и викторины** (меню «+»), кнопка «вниз», обои и стеклянные панели, новый экран входа с градиентом.
