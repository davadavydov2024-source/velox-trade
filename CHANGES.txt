2FA (ДВУХФАКТОРНАЯ АУТЕНТИФИКАЦИЯ) — что внутри архива

НОВОЕ:
  src/lib/totp.ts                    — сам алгоритм TOTP (как в Google Authenticator), написан
                                        на встроенном crypto Node.js, без сторонних библиотек
  src/app/api/2fa/setup/route.ts      — начать подключение: генерирует секрет + QR-код
  src/app/api/2fa/verify-setup/route.ts — подтвердить код из приложения → включает 2FA,
                                        выдаёт 10 резервных кодов (показываются один раз)
  src/app/api/2fa/verify-login/route.ts — проверка кода при входе (TOTP или резервный код)
  src/app/api/2fa/disable/route.ts    — отключение (требует текущий код — просто так,
                                        через угнанную сессию, отключить нельзя)
  src/components/TwoFactorGate.tsx    — блокирует весь сайт экраном "введи код", если у
                                        аккаунта включена 2FA и в этой вкладке её ещё не
                                        подтверждали (по образцу уже существующего BanGate)
  src/components/TwoFactorCard.tsx    — карточка в Профиль → Безопасность: включить (QR +
                                        резервные коды) / отключить

ИЗМЕНЕНО:
  src/app/providers.tsx        — подключён TwoFactorGate (между BanGate и MaintenanceGate)
  src/app/profile/security/page.tsx — добавлена карточка 2FA под переключателем push-уведомлений
  src/types/index.ts           — добавлено поле twoFactorEnabled в UserProfile (сам секрет и
                                  резервные коды НЕ хранятся в этом поле — они в отдельной
                                  серверной коллекции twoFactorSecrets, недоступной с клиента)
  package.json                 — добавлена библиотека qrcode (рисует QR-код для приложения-
                                  аутентификатора). ВАЖНО: это полная замена файла — если ты
                                  сам добавлял другие пакеты после нашей прошлой сессии, впиши
                                  их обратно вручную после распаковки, иначе они потеряются.

КАК ЭТО РАБОТАЕТ:
- Профиль → Безопасность → "Включить" → сканируешь QR-код в Google Authenticator (или
  любом другом TOTP-приложении) → вводишь код для подтверждения → получаешь 10 резервных
  кодов (сохрани их — без телефона они единственный способ войти).
- После этого при каждом входе в аккаунт (в новой вкладке/после закрытия браузера) сайт
  будет спрашивать код, прежде чем показать что-либо внутри.
- Отключить можно только зная текущий код — просто кнопки "выключить" без проверки нет.

ЧЕСТНО ПРО ОГРАНИЧЕНИЯ (важно понимать):
Это НЕ встроенная в Firebase MFA (у Firebase такая есть, но требует включения Identity
Platform в консоли Google — то есть отдельного шага в настройках проекта и потенциально
платного тарифа, чего я не могу сделать и проверить за тебя). Вместо этого сделано на
уровне приложения: Firebase пускает пользователя как обычно, а сайт поверх блокирует
интерфейс, пока не введён код. Разница на практике: обычному пользователю через сайт — это
полноценная защита. Но теоретически кто-то, кто получит доступ к Firebase ID-токену
пользователя В ОБХОД сайта (например, через скомпрометированный клиент, который сам
общается с Firebase API напрямую), может обратиться к серверным API в обход этого экрана,
потому что сами API-роуты (заказы, платежи и т.д.) сегодня проверяют только валидность
токена, а не факт прохождения 2FA. Для большинства реальных сценариев угона аккаунта
(украденный пароль, подобранный пароль) это полностью закрывает проблему. Если нужно
защититься и от продвинутых атак через API — это отдельная, более крупная доработка
(отметка "2FA пройдена" непосредственно в самих защищённых API-роутах), скажи отдельно,
если это нужно.

Применить: распаковать поверх проекта, как и раньше — но после этого архива на Vercel
при следующем деплое должно пройти `npm install` заново (новый пакет qrcode), это
произойдёт само, ничего руками делать не нужно.
